# SWEEPR Cleaner (`sweeprcleaner.com`) — Daily White-Hat Security Audit & Auto-Remediation Log

## 2026-10-31 — Daily White-Hat Security Audit & Auto-Remediation Pass
- **Scope**: Server/website (`server`), Desktop app (`app/src-tauri` & `app/src`), and Shared CRM (`sweepr_crm`).
- **Finding 1 (Full-Spectrum IPv4 & IPv6 Private Address Bypass in Pricing Geo-Lookup & External API Leakage)**: In `server/src/pricing.ts` and `sweepr_crm/src/pricing.ts` (`isPrivateOrLoopbackIp`), IP verification prior to dispatching third-party geo queries (`api.country.is`, `get.geojs.io`) only verified `127.0.0.1`, `::1`, `0.0.0.0`, and basic RFC 1918 prefixes. It failed to reject full IPv4 loopback ranges (`127.0.0.0/8`, e.g. `127.0.0.2`), current network (`0.0.0.0/8`), Carrier-Grade NAT (`100.64.0.0/10`), multicast/reserved (`224.0.0.0/4`, `240.0.0.0/4`, `255.255.255.255`), documentation/benchmark blocks, IPv6 unique-local (`fc00::/7`), link-local (`fe80::/10`), multicast (`ff00::/8`), uncompressed loopbacks (`0:0:0:0:0:0:0:1`), and IPv4-mapped/compatible private addresses. As a result, internal IP topologies were queried against external third-party services.
  - **Remediation Implemented**: Replaced `isPrivateOrLoopbackIp` in both codebases with full-spectrum RFC-compliant IPv4 and 8-word IPv6 decomposition (`isPrivateIpv4Parts` and `parseIpv6Words`), treating any private, loopback, multicast, documentation, or non-IP input as local to prevent external outbound leaks. Added unit test suite in `server/test/security.test.ts` and `sweepr_crm/test/v1-licensing.test.ts`.
- **Finding 2 (Missing CSRF Origin Validation on Customer Portal Device Removal)**: In `server/src/app.ts` (`/api/portal/devices/remove`), while other customer portal endpoints enforce `isSameOriginRequest(c, config.publicUrl, trustProxy)`, this state-changing POST endpoint omitted CSRF origin validation. Because the endpoint authenticates via ambient browser session cookies, an attacker site could issue unauthorized cross-origin device unlinking requests.
  - **Remediation Implemented**: Enforced `!isSameOriginRequest(c, config.publicUrl, trustProxy)` returning `403 forbidden_origin` at the entry of `POST /api/portal/devices/remove`. Added regression test verifying cross-origin CSRF rejection.
- **Finding 3 (Desktop App Cloud Sync & Offload Source/Destination Protection Bypass)**: In `app/src-tauri/src/cloud_sync.rs` (`add_pair`), defensive validation guarded only the destination directory (`dst`), leaving the source folder (`src`) unchecked against protected system paths or the internal application `data_dir`. In addition, `app/src-tauri/src/cloud.rs` (`offload_cloud_files`) did not verify destination containment within `data_dir`.
  - **Remediation Implemented**: Enforced `!crate::duplicates::is_protected_system_path(&src)`, `safety::is_safe_root(&src)`, and `!safety::is_within(&src, data_dir)` in `cloud_sync::add_pair`. Added `offload_cloud_files_with_data_dir` checking destination containment against `data_dir` and wired it through `cloud_commands.rs`. Added regression assertions asserting rejection of `data_dir` as source/destination in `cloud_sync::tests`.
- **Finding 4 (Central CRM Impersonation Nonce Replay Hardening)**: In `sweepr_crm/src/app.ts` (`/dashboard`), the impersonation session handler permitted token verification to proceed without a `jti` nonce if omitted (`if (verified.jti)`), allowing potentially non-expiring replay of hand-crafted impersonation tokens.
  - **Remediation Implemented**: Enforced that `verified.jti` is strictly mandatory and checked against `consumedImpersonationNonces`, instantly redirecting to `/login` if absent or previously consumed.
- **Finding 5 (Outbound Peer Notification Request Timeout & Socket Exhaustion Guard)**: In `sweepr_crm/src/app.ts` (`notifyVpnPeerRevocation`), outbound notification POSTs to peer revocation webhooks were dispatched without an `AbortSignal.timeout()`, risking hanging socket leaks if a remote peer server stalled.
  - **Remediation Implemented**: Added `signal: AbortSignal.timeout(5000)` to outbound fetch requests.
- **Finding 6 (Backlink Verifier SSRF Port Smuggling & Dangerous Protocol Port Defense)**: In `server/src/seo/backlinks.ts` and `sweepr_crm/src/seo/backlinks.ts` (`isPublicHttpUrl`), port constraints were not enforced, allowing public URLs to target non-HTTP services (e.g. port 25 SMTP, port 22 SSH, port 6379 Redis).
  - **Remediation Implemented**: Constrained permissible ports in `isPublicHttpUrl` strictly to standard web ports (80, 443, 8080, 8443). Added regression test assertions in server and CRM test suites.
- **Finding 7 (Cookie Domain Allowlist Normalization RFC Compliance)**: In `app/src-tauri/src/commands.rs` (`normalize_domain`), domain allowlist inputs were sanitized only for whitespace and basic dots, permitting special characters before interpolation into cookie cleanup SQL `LIKE` clauses.
  - **Remediation Implemented**: Upgraded `normalize_domain` to enforce strict RFC hostname label validation (`[a-z0-9-]`, no consecutive dots, label lengths 1-63, total length ≤ 253). Added test suite verifying rejection of injection attempts.
- **Finding 8 (Central CRM Sync Cleartext HTTP Defense in Production)**: In `server/src/crm-sync.ts` (`getCrmUrl`), central CRM URLs were loaded directly from environment configuration without asserting TLS encryption in production environments.
  - **Remediation Implemented**: Enforced that in production (`NODE_ENV === "production"`), `getCrmUrl()` requires `https://`, treating plaintext `http://` configurations as unconfigured to prevent cleartext exposure of API keys and customer licensing tokens.
- **Finding 9 (Windows Explorer Process Hijacking Defense in Native Reveal)**: In `app/src-tauri/src/commands.rs` (`reveal_in_folder`), Windows Explorer was invoked using an unqualified `"explorer"` executable string without resolving the system directory.
  - **Remediation Implemented**: Resolved canonical `%SystemRoot%\explorer.exe` (fallback `C:\Windows\explorer.exe`) preventing current-working-directory binary planting.

## 2026-10-29 — Daily White-Hat Security Audit & Auto-Remediation Pass
- **Scope**: Server/website (`server`), Desktop app (`app/src-tauri` & `app/src`), and Shared CRM (`sweepr_crm`).
- **Finding 1 (Full-Spectrum IPv6 & Non-Standard IPv4 SSRF Bypass Prevention)**: In `server/src/seo/backlinks.ts` and `sweepr_crm/src/seo/backlinks.ts` (`isPublicHttpUrl`), expanded IPv6 loopback (`http://[0:0:0:0:0:0:0:1]/`), uncompressed zero addresses (`http://[0:0:0:0:0:0:0:0]/`), IPv4-compatible representations (`http://[0:0:0:0:0:0:127.0.0.1]/`), and non-standard dotted IPv4 notations (octal e.g. `0177.0.0.1`, shorthand `127.1`, or mixed hex `0x7f.0.0.1`) bypassed simple prefix string checks and `isIP()` validation.
  - **Remediation Implemented**: Implemented RFC-compliant 8-word IPv6 decomposition (`parseIpv6Words`) in both repositories, validating against loopback, unspecified, unique-local (`fc00::/7`), link-local/site-local (`fe80::/9`), multicast (`ff00::/8`), discard, and embedded IPv4 private ranges. For IPv4, added strict validation rejecting octal leading zeros, non-4-part dotted notations, and hex segments. Added comprehensive regression tests across server and CRM test suites.
- **Finding 2 (Outbound Service Notification Plaintext HTTP & API Key Leakage Prevention)**: In `sweepr_crm/src/app.ts` (`notifyVpnPeerRevocation`), outbound notification POSTs transmitting `x-sweepr-api-key` and `x-crm-api-key` could target plaintext `http://` URLs on remote peer sites, presenting a risk of cleartext API key interception over the network.
  - **Remediation Implemented**: Enforced that in production environments (`NODE_ENV === "production"`), outbound revocation webhooks strictly require encrypted `https://` endpoints.
- **Finding 3 (Desktop App Safety Path Equivalence & Slashes Normalization Bypass Guard)**: In `app/src-tauri/src/safety.rs` (`paths_equal`), path comparisons only stripped trailing backslashes and compared strings case-insensitively without normalizing forward slashes or Windows verbatim prefixes (`\\?\`). Comparing a forward-slash formatted path (e.g. `C:/Users/.../Downloads`) against denied roots returned `false`, bypassing safe root checks.
  - **Remediation Implemented**: Replaced `paths_equal` with `normalise_for_compare(a) == normalise_for_compare(b)`, standardizing separators, verbatim prefixes, trailing slashes, and casing. Added regression test `paths_equal_handles_mixed_separators`.
- **Finding 4 (Desktop App Cloud Offload & Sync Protected System Path Traversal Defense)**: In `app/src-tauri/src/cloud.rs` (`offload_cloud_files`) and `app/src-tauri/src/cloud_sync.rs` (`add_pair`), user-specified target and destination directories were only checked for existence, leaving system folders (`C:\Windows`, `C:\Windows\System32`, `C:\Program Files`) and internal application data directories (`data_dir`) exposed to file offloading or sync operations.
  - **Remediation Implemented**: Enforced `is_protected_system_path`, `!safety::is_safe_root`, and `safety::is_within(..., data_dir)` checks on destination directories before allowing cloud offload or sync pair registration.
- **Finding 5 (Shared CRM Form Submission CSRF & Allowed Origins Parity)**: In `sweepr_crm/src/security.ts` (`adminBasicAuth` and `isSameOriginRequest`), HTML form submissions (`application/x-www-form-urlencoded`, `multipart/form-data`, `text/plain`) lacked explicit rejection for non-same-origin Fetch Metadata, and `allowedOrigins` in `sweepr_crm/src/app.ts` was not normalized via URL origin parsing.
  - **Remediation Implemented**: Added form CSRF guards requiring explicit same-origin/same-site Fetch Metadata in CRM Basic Auth and same-origin validation, and normalized `allowedOrigins` using `new URL(config.publicUrl).origin`. Added regression test in `test/v1-licensing.test.ts`.

## 2026-10-23 — Daily White-Hat Security Audit & Auto-Remediation Pass
- **Scope**: Server/website (`server`), Desktop app (`app/src-tauri` & `app/src`), and Shared CRM (`sweepr_crm`).
- **Finding 1 (Rate Limiter DoS / Lockout Eviction Flush Prevention)**: In `server/src/security.ts` (`createRateLimiter`), cache eviction on `hits.size > maxKeys` operated in FIFO order. A high-frequency key-flooding attack could evict active administrative or brute-force lockouts.
  - **Remediation Implemented**: Prioritized eviction of low-hit (non-blocked, `v.n < limit`) keys so active lockout state is preserved across key flushes. Added regression test asserting blocked key survival.
- **Finding 2 (Strict CSRF Form Submission Guard)**: In `server/src/security.ts` (`isSameOriginRequest` and `adminBasicAuth`), requests omitting both `Origin` and `Sec-Fetch-Site` lacked explicit form content-type validation, allowing potential HTML `<form>` CSRF from privacy clients or legacy browsers.
  - **Remediation Implemented**: Enforced that standard HTML form types (`application/x-www-form-urlencoded`, `multipart/form-data`, `text/plain`) require explicit same-origin/same-site metadata. Added test asserting form post rejection.
- **Finding 3 (HSTS Preload Directive Parity in Shared CRM)**: In `sweepr_crm/src/security.ts` (`securityHeaders`), the `Strict-Transport-Security` header lacked the `preload` directive.
  - **Remediation Implemented**: Upgraded header to `max-age=31536000; includeSubDomains; preload` for full browser HSTS preload list eligibility.
- **Finding 4 (CRM Auth Middleware Route Path Boundary & Slash Normalization)**: In `sweepr_crm/src/app.ts`, routes were guarded using prefix strings (`/crm`, `/crm/*`, `/admin`, `/api/crm/*`). Requests without a trailing slash (`/api/crm`) or with multiple/URL-encoded slashes could bypass route guards.
  - **Remediation Implemented**: Replaced with unified regex router middleware `ADMIN_PATH_RE = /^\/+(api\/+crm|crm|admin)(\/|$)/i` combined with `decodeURIComponent` and slash collapsing.
- **Finding 5 (PowerShell Execution Path Defense in Device ID Detection)**: In `server/src/crm.ts` (`getLocalWindowsDeviceId`), `execSync('powershell -Command ...')` called an unquoted `powershell` command without resolving the system root directory, presenting potential PATH/CWD hijacking vulnerabilities on Windows host environments.
  - **Remediation Implemented**: Resolved canonical system path `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` with `-NoProfile -NonInteractive` flags.
- **Finding 6 (Desktop App Native Dialog Environment Isolation)**: In `app/src-tauri/src/commands.rs` (`pick_folder` and `pick_file`), dialog prompts were sanitized via single-quote doubling and interpolated directly into PowerShell script strings.
  - **Remediation Implemented**: Passed prompts strictly via process environment variable `$env:SWEEPR_PROMPT` with `-NoProfile -NonInteractive -STA`, eliminating script string concatenation.
- **Finding 7 (Desktop App Portable Binary / Uninstaller Hijacking Defense)**: In `app/src-tauri/src/commands.rs` (`uninstall_self`), when executed in portable mode, the process checked `parent.join("uninstall.exe")` and spawned it. If running from user-writable directories (Downloads, Desktop, Temp), an attacker could drop a rogue `uninstall.exe`.
  - **Remediation Implemented**: Added safety check preventing execution of `uninstall.exe` if located inside `download_dir()`, `desktop_dir()`, or `temp_dir()`.
- **Finding 8 (Shared CRM VPN Revocation Outbound SSRF & API Key Leakage Guard)**: In `sweepr_crm/src/app.ts` (`notifyVpnPeerRevocation`), notification POSTs containing `x-sweepr-api-key` were dispatched to `vpnProj.siteUrl/api/vpn/revoke` without verifying if the target was a public URL.
  - **Remediation Implemented**: Enforced `isPublicHttpUrl` validation before making outbound HTTP calls to remote project site URLs, preventing API key exposure to private networks or cloud metadata.
- **Finding 9 (SSRF IP Filter Range Hardening)**: In `server/src/seo/backlinks.ts` and `sweepr_crm/src/seo/backlinks.ts` (`isPublicHttpUrl`), IPv4 checks lacked explicit exclusion for multicast/Class E (`a >= 224`), TEST-NET blocks (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24), and benchmarking (198.18.0.0/15).
  - **Remediation Implemented**: Extended IPv4 filtering to block all reserved, multicast, documentation, and benchmarking blocks. Added regression test assertions.
